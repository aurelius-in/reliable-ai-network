2.1 RLS posture

  • User JWT: read/write own creations, assets, progress, profile fields allowed by policy.
  • Service role: webhooks, analytics insert, referral credit writes, lead/unsubscribe, admin reads.
  • Public must not insert into analytics_events or billing_events directly.

03Required API contracts (evidence of slice)

Minimum set that proves the product vertical slice is live:

  1. POST /api/stripe/checkout returns embedded clientSecret for a mapped price.
  2. POST /api/stripe/webhook verifies signature; syncs profile; records billing_events.
  3. POST /api/creations creates a row owned by the session user.
  4. At least one Starter tool (/api/analyze or /api/pricing) returns JSON and persists generated_assets.
  5. At least one Growth tool returns 403 for Starter-only entitlements and 200 for Growth+.
  6. POST /api/track accepts beacon and inserts via service role.
  7. POST /api/checklist + POST /api/unsubscribe enroll and stop nurture.

08Suggested proof plan for critics

  1. Auth: Create account; confirm middleware blocks /dashboard when logged out.
  2. Billing: Start Checkout in test or carefully in live; confirm profile tier after webhook.
  3. Tool: Run analyzer; inspect generated_assets for user.
  4. Gate: With Starter (non-trial), call Growth API; expect 403.
  5. Referral: Attribute ref; complete first paid invoice; expect balance credit + reward row.
  6. Nurture: Submit checklist; receive email 1; unsubscribe; confirm no further sends.
  7. Ops: Hit /api/track; see row in analytics_events.
