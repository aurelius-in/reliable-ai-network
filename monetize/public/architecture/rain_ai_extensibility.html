AI extensibility model

01Thesis

AI is the reasoning layer, not the authority. Make it RAIN uses Grok to produce structured monetization artifacts under application-owned prompts and tier gates. Humans (creators) accept, edit, or discard outputs. Stripe and Supabase remain the systems of record for money and identity.

  • Prefer JSON contracts over chat transcripts as product state.
  • Keep entitlement, pricing of RAIN itself, and referral math out of prompts.
  • Use external data (Apollo) when facts matter more than generation.

What AI does

  • Draft ICPs, pricing options, funnels, plans, content, strategy packs
  • Summarize “what’s working” from creator-entered metrics
  • Return parseable JSON for UI rendering and storage

What AI does not

  • Charge cards or change current_tier
  • Write arbitrary SQL or weaken RLS
  • Send email or Apollo sequences autonomously
  • Act as legal/tax/securities advice

03Canonical tool pipeline

1. Authenticate session
2. requireTier(required)     // Growth / Pro tools
3. resolveCreation(...)      // owned creation or example context
4. Build messages from prompts/{tool}.ts
5. grokChatJSON<T>({ model, response_format: json_object })
6. Validate / shape for UI
7. INSERT generated_assets
8. trackToolRun(...)
9. Return payload

Implementation anchors: lib/grok.ts, lib/tool-request.ts, route handlers under app/api/*. Long-running routes set maxDuration = 300.

06Prompt ownership

  • Each Grok-backed tool has a module under prompts/ (system + user assembly).
  • Default model: GROK_MODEL or grok-4.5 via lib/grok.ts.
  • Response format forced to JSON object for schema-shaped UI.
  • Policy: commercial rules (trial length, referral percent, tier ranks) live in TypeScript, not in prompt text as authority.
Prompts may describe the creator’s domain. They must not be the store of entitlement truth.

07Non-goals

  • Training or fine-tuning a proprietary foundation model in v1.
  • Agentic loops that spend money or email prospects without explicit UI actions.
  • Replacing Stripe Customer Portal with model-mediated cancellation.
  • Unstructured “chat with your business” as the primary UX (journey tools remain primary).
  • Claiming deterministic market truth from generation alone.

08Extensibility recipe

To add a sixteenth tool without breaking the architecture:

  1. Add journey metadata in lib/journey.ts (phase, tier, completion rule).
  2. Add prompt module if reasoning is required.
  3. Add app/api/{tool}/route.ts following the canonical pipeline.
  4. Enforce requireTier consistent with journey floor.
  5. Persist a new generated_assets.type (or milestone) and wire UI.
  6. Emit trackToolRun; document the route in Logical API map.

Future-friendly seams

  • Swap model provider behind grokChatJSON without changing tool routes.
  • Add retrieval over a creator’s prior assets before prompting.
  • Optional tool-calling / MCP bridges for ops, still behind policy layer.
Authority reminder for critics: if a proposed feature lets the model change billing or RLS, it is rejected by this architecture.
