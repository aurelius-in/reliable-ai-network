2.1 Asset typing (logical)

Tool outputs land in generated_assets with a type that journey logic understands (analysis, pricing, funnel, strategy_*, dfy_request, etc.). Library/premium completion may also use client visit markers; that is an engineering detail called out in Implementable.

03Logical component model

Identity & session

Does: Supabase email/password; cookie session refresh in middleware; protect dashboard/billing/onboarding; profile ensure on signup paths.

Does NOT: Own subscription tier truth; call Grok; write Stripe.

Entitlement & billing sync

Does: Checkout session creation; portal sessions; webhook verification; map price → tier; write profile fields; append billing_events; trigger referral credit on first paid invoice.

Does NOT: Trust client-posted tier; run nurture email content generation via Grok.

Tool orchestration

Does: Authenticate; resolve creation; requireTier for Growth/Pro; load prompt module; call grokChatJSON; persist asset; track tool_run.

Does NOT: Mutate Stripe; bypass RLS with user JWT for other users’ rows.

Enrichment (Apollo)

Does: People search for ICP; company enrich for competitor strategy.

Does NOT: Become the system of record for CRM; authorize sends.

Growth: referrals & nurture

Does: Attribute ref codes; credit 50% of amount_paid; checklist capture; schedule Resend sequence; honor unsubscribe.

Does NOT: Cap lifetime referral earnings (product rule: stacks, no cap); send after unsubscribe.

Counter (analytics)

Does: Accept beacon events; store name/path/UTM/session/user/props; admin aggregates behind secret.

Does NOT: Affect entitlement; expose PII beyond what the event payload already contains.

5.3 Referral reward

invoice.payment_succeeded (amount_paid > 0)
  → load referee profile (referred_by set, not yet rewarded)
  → credit = 50% of amount_paid
  → insert referral_rewards (unique referee)
  → Stripe customer balance transaction on referrer

06Tier gating logic

  • Ranks: starter = 1, growth = 2, pro = 3. Access is inclusive upward.
  • Null tier = Free (marketing surfaces only; tools require auth and often a paid/trial tier).
  • Trial: product places current_tier = pro while trial is active so the full journey is evaluable.
  • UI locks via lib/journey.ts; API enforces via requireTier on Growth/Pro routes.
  • Starter AI routes require authentication; Growth/Pro routes require both auth and tier.
Price ID → tier mapping is configuration in lib/stripe.ts / env (STRIPE_PRICE_*). See Implementable.
