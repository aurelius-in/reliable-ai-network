01Problem and product thesis

Make it RAIN is a subscription SaaS that helps software and AI creators turn an idea or product into a priced offer, find buyers, launch distribution, and measure what works. The product is a guided 15-tool journey, not a chat toy and not a generic CRM.

  • Creators stall between “I built something” and “someone paid me.”
  • Advice is scattered; execution assets (pricing, funnels, outreach, plans) are not.
  • RAIN packages that path into tiered tools with durable artifacts per creation.

02Architectural pattern

RM-ODP-aligned separation of concerns, implemented as a thin Next.js application with clear authority boundaries:

Authority

Stripe webhooks own subscription state. Supabase RLS owns data access. AI proposes artifacts; it does not authorize billing or mutate entitlements.

Composition

One vertical slice: Auth → Creation → Tool run → Saved asset → Next best action. Everything else (referrals, nurture, Counter) orbits that slice.

05Strongest AI value

  • Contracted JSON outputs via Grok (response_format: json_object), not freeform chat.
  • Prompt modules per tool under prompts/; business rules and tier gates stay in application code.
  • Enrichment, not invention, for leads: Apollo for people/company data when ICP is known.
  • Human authority: creators edit, discard, or re-run; AI never charges a card or upgrades a tier.
Detail lives in AI Extensibility. Wire contracts live in Logical and Implementable docs.

07What the platform does NOT do (today)

  • Does not host the creator’s product runtime or payment processor for their end customers.
  • Does not act as a marketplace or escrow between creators and buyers.
  • Does not let the model authorize subscription changes or write Stripe state.
  • Does not train proprietary foundation models; it orchestrates a contracted reasoning API.
  • Does not expose this architecture site in product navigation or the public sitemap.
